Sign in and secure the administrator account

Use the administrator details supplied with your purchase.

This information appears throughout the system.

  1. Open Settings from the administrator menu.
  2. Enter your organisation name and upload a PNG, JPG or WebP logo.
  3. Review the email address used for system messages.
  4. Save, then return to the dashboard to check the result.
3

Run a complete test

Test the whole journey before using the system for real work.

  1. Create a clearly labelled TEST permit.
  2. Submit it for approval and sign in as a manager.
  3. Approve the permit and open its public link or QR code.
  4. Record that work started, then close the permit.
  5. Confirm that emails, history and status changes are correct.
02

For permit users

Everyday permit tasks

Short guides for the actions people use most often.

＋Create a permitChoose a template, complete it and submit
  1. Select Create permit.
  2. Choose the permit type that matches the work.
  3. Enter the holder, location and valid dates.
  4. Answer every required safety question.
  5. Add supporting photos or documents if needed.
  6. Review the summary, then select Submit for approval.

Tip: Save accurate details. A permit is a safety record, not just a form.

✓Review a permitApprove or reject safely
  1. Open Manager approvals.
  2. Read the work details, dates and safety answers.
  3. Check any photographs and attachments.
  4. Select Approve only when the work can proceed safely.
  5. If rejecting, give a clear reason so the applicant knows what to correct.
▦Use a QR codeOpen the public permit view
  1. Open the permit and locate its QR code.
  2. Print or display it at the work location.
  3. Workers scan it with their phone camera.
  4. Check the permit reference and status before starting work.

Safety check: Never begin work from an expired, rejected or closed permit.

■Start and close workKeep the live status accurate
  1. Open the active permit using its link or QR code.
  2. Select Start work when work actually begins.
  3. When complete, sign in and select Close permit.
  4. Add a closure note if there is anything the safety team should know.
↑Add evidenceUpload photos and documents

The internal permit screen accepts JPG, PNG, GIF, WebP and PDF files up to 10 MB. Public media questions may also accept supported video files up to 25 MB.

Use clear, relevant images and avoid uploading personal information that is not needed for the permit.

Add a team member

  1. Open Admin → Users.
  2. Select Create user.
  3. Enter their name and work email.
  4. Choose the least-powerful role they need.
  5. Ask them to change their initial password.

Review permit templates

Keep only the templates your organisation actually uses. Test changes with a draft permit before making them part of a live process.

Configure email

Add the SMTP details supplied by your email provider, save them, then complete a test approval. Never paste email passwords into support messages or screenshots.

Review activity

Use the activity log to understand important account and permit events. Review unusual actions promptly and retain records according to your policy.

Back up safely

Create regular encrypted backups and store a copy away from the website. Test restoration periodically; an untested backup is not a recovery plan.

Check expiry automation

Confirm the scheduled expiry and notification tasks are running. A hosting provider or developer can check this if you do not manage the server.

04

For source-code customers

Install the website

Ask your hosting provider or developer to complete this section if you are not comfortable managing a web server.

Not an IT specialist?

Send this section to your hosting provider. Do not guess database settings or share passwords by ordinary email.

  1. 1

    Check the hosting

    Use PHP 8.1 or later, MySQL 5.7+/MariaDB 10.2+, HTTPS, and the PHP extensions listed in composer.json.

  2. 2

    Upload the code

    Place the application in the website document root. Private folders such as src, vendor, data and backups must not be publicly accessible.

  3. 3

    Install dependencies

    composer install --no-dev --classmap-authoritative

    This creates vendor/autoload.php. The website cannot start without it.

  4. 4

    Create the database

    For a new installation, import database/database.sql. For an existing installation, import each newer file from database/imports in date order.

  5. 5

    Configure the environment

    Copy .env.example to .env, then add the real website URL, database account, mail settings and newly generated notification keys. Keep this file private.

  6. 6

    Run verification

    php bin/migrate.php
composer check

    Confirm the login, uploads, email, QR links, approvals and scheduled tasks in a test environment before launch.

Never publish secrets.Do not commit .env, database exports, backups or API keys to GitHub.

A short routine prevents most avoidable problems.

  • Check failed emails or scheduled tasks

  • Confirm backups completed

06

When something goes wrong

Quick troubleshooting

Start with the message or symptom you can see.

The page mentions “vendor/autoload.php”

The application dependencies have not been installed. From the website folder, the hosting provider should run:

composer install --no-dev --classmap-authoritative
The website cannot connect to the database

Check the database name, host, username and password in the private .env file. Confirm the database user has access from the web server.

Email messages are not arriving

Check the SMTP settings, sender address and mail password. Confirm the email queue scheduled task is running, then inspect the server log without exposing credentials.

A QR code opens the wrong address

Check that APP_URL contains the full HTTPS website address and no old test domain. Generate the QR code again after correcting it.

A photo or document will not upload

Use a supported file type and stay within the displayed size limit. If all uploads fail, ask the host to check folder permissions and PHP upload limits.

I cannot stay signed in

Confirm the website uses HTTPS, cookies are allowed, and SESSION_COOKIE_SECURE=true on the live website. An administrator can also check that the account remains active.
